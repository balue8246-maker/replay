# REPLAY 设计：指挥 / 判断 / 功能

## 1. 三个角色

| 角色 | 谁 | 负责 | 不负责 |
|---|---|---|---|
| **指挥** | 慢模型（全能模型，如 Opus） | 把任务拆成一串阶段、定每段的子目标和完成证据；处理异常、等待、人工节点；从录制中学习、修补技能 | 不逐个读页面元素，不判断"这个页面加载好了没" |
| **判断** | 快模型 Jev（单次约 0.4–1 秒） | 看什么：页面上哪些东西和当前子目标有关；点哪个：下一步操作哪个元素、哪个值填进哪个框；现在怎样：加载完没有、有没有报错或弹窗、这一步成功没有、子目标完成没有、是不是卡住了 | 不能打开页面、点击、打字；不能生成文字、读长内容、看像素；不做规划，也不决定风险 |
| **功能** | 慢模型手里的工具 | 打开页面、取快照/元素树、截图和看图、点击、输入、下载、系统对话框、把截图转成"框+文字" | 不做决定 |

功能属于慢模型这一侧，Jev 本身什么动作都做不了。但"慢模型这一侧"不等于每个动作都要慢模型想一轮：功能是普通代码，可以由指挥直接调用，也可以由内循环在指挥划定的范围内，自动执行 Jev 选中的那一步。

## 2. 一个任务怎么跑

```
指挥（慢）：拆出阶段 1..N，每段写好 子目标 + 可用的值 + 完成证据
  └─ 阶段 k
       内循环（快慢交替，以代码为主）：
         功能：观察（快照 / 元素树 / 截图转文字）
         判断：Jev 一次回答——哪些相关、下一步做什么、现在什么状态
         ├─ 把握高 + 动作安全可撤回 → 功能：直接执行 → 再观察
         ├─ 子目标完成 → 功能：用独立证据核验 → 回到指挥
         └─ 拿不准 / 有风险 / 要自由文本 / 读不到文字 / 卡住
              → 把 Jev 压缩后的视图（约 10 行候选 + 状态）交给指挥
              → 指挥决定，调用功能执行 → 回到内循环
  └─ 阶段之间：指挥处理等待/轮询、人工节点（扫码、审批）、失败只修这一段
```

快在两处：

1. **Jev 有把握的步骤不需要指挥参与。**
2. **需要指挥时，它读的是 Jev 压缩后的 10 行左右，而不是几千个元素或一张截图。**

"页面好了没、出错没、做完没"这类检查都交给 Jev，指挥调用的次数因此少很多。

## 3. Jev 的题型

每次观察后最多一两次请求，题目一起发：

| 问题 | 题型 | 用途 |
|---|---|---|
| 当前子目标下一步该操作哪个元素 | choice（候选 ≤255，加 `none`） | 执行或交给指挥 |
| 每个候选和子目标的相关度 | score | 生成给指挥看的压缩视图 |
| 某个值填进哪个框 | choice（只在用户提供的值里选） | 填表；没有合适的值就交给指挥，不编造 |
| 上一步成功了吗 / 有报错吗 / 弹出窗口了吗 / 子目标完成了吗 / 卡住了吗 | noul | 状态机 |

置信度不能单独放行（参考 CUA-S1：41 个错误里有 36 个是在 0.974 置信度下跳过的）。所以放行条件是：置信度够高 + 和第二名拉开差距 + 执行后状态检查通过。三者有一项不满足就交给指挥。

以下动作一律交给指挥确认：提交、支付、删除、发送，以及需要自由文本、登录或扫码的步骤。

## 4. 感知：先给文字，最后才看图

| 界面 | 观察方式 | Jev 能否判断 |
|---|---|---|
| 网页 | Ego 快照 + DOM 中可点击的元素（ego-jev 已实现） | 能 |
| 桌面 App | cua-driver 元素树（角色、名字、值） | 能 |
| 系统对话框（打开/存储窗口、提示框） | Peekaboo 读对话框的按钮和文字，`choose` 一步选路径 | 能 |
| 读不到结构的界面（画布、远程桌面） | 截图 → macOS Vision 识别出"框+文字"（截图前必须确认目标窗口在最前） | 转成文字后能 |
| 只能看图的情况 | 截图交给指挥 | 不能，最后手段 |

## 5. 录制的作用

人做一遍之后，由指挥整理出两样东西：

- **任务链草稿**：分哪几段、每段的子目标、哪些输入会变、每段怎么证明做完了。
- **每一步的提示**："上次点的是叫'导出'的按钮，点完触发了下载"。这些提示有三个用处：
  - 喂给 Jev 出题时加权，让它扫得更准；
  - 作为执行后的预期结果，用来核验这一步；
  - 录下的定位器作为一层缓存：先用它试，试完照样让 Jev 检查状态，而不是闭眼重放。

全程不调用模型的直接重放，只用在跑过多次都没出错的固定段落上。只要出一次错就降级回内循环。

## 5b. 学会 ≠ 录下轨迹（v0.3）

人说"我演示一遍"，真正想要的是 agent 下次**懂**这件事：哪些每次会变、怎么定，哪些固定不动，做对了怎么核验，遇到页面变化时按意图去找。单靠录轨迹给不了这些，所以跟学分成五步：

1. **先问**（`teach start` / `brief`）。目标、产出、系统、会变的输入以及怎么定、固定项、频率、怎么证明做对、常见坑、拿到之后做什么。只问请求里没说清的，合成一条消息问。
2. **边做边说**（`teach record`）。动作照常录；讲解有三个入口：麦克风（本机 macOS 语音识别，按时间戳对齐到动作）、页面右下角的打字框、在聊天里说（`teach note`）。讲解对齐规则：挂到讲解开始后最先发生的那个动作上（填写类动作允许更长的提前量），后面没有动作时挂到前一个动作。
3. **理解稿 + 复述确认**（`understanding.md`）。代码先做能确定的事：讲解挂到步骤上；按讲解里的词判断参数是"会变"还是"固定"（"不一样/这次是"比"每次都"优先）；找出误操作，包括去了又马上回来、同一控件连点几次夹着杂按键；列出页面背后的接口和查询参数；记下下载；摘出讲解里说的核验方法。然后由指挥用 3–5 句话复述，并把剩下的问题一次问完。这一步就是"probe"：问的是规则，不是重复步骤。
4. **编译**（`teach compile`）。产出 `procedure.md`（写意图的做法）和 `plan.json`。值写成 `{{key}}`，确认过的误操作删掉，但上面挂的讲解留下来；"行数等于页面总数"编译成 `rows:'page'`；分页步骤加 `skipIf: allOnPage`，已经一页显示全部就跳过。
5. **监督试跑**（`teach trial`）。换一组输入跑，在产出结果的那一段前停下等人确认；出问题就用 `teach correct` 写回，重新编译。确认后才 `save`，以防轨迹投毒。

自学（`replay explore`）把同一件事反过来做：不演示，agent 自己只读地逛一遍网站。每页调一次 Jev，给页面打标签（列表/筛选/可导出/报表/表单/相关度），并决定下一步展开哪个链接；按模板去重详情页；只点导航、标签页和展开项，不点提交、新建、删除、导出这类按钮。产出 `sitemap.json` 和 `manual.md`（网站地图、数据在哪、每页的筛选/列/总数/导出入口/接口、还没逛到的）。拿到一句需求时：

- 先选页：需求里点名了某页标题（例如 "Ready to Deploy"）就直接用它，不然由 Jev 选；
- 设筛选（每个给定的值都填进去就算完成，不靠 Jev 判断完成）；
- 列表分页且要全部数据时，先把所有记录调到一页（已经满足就跳过）；
- 导出：手册里记下了"导出按钮 → 格式项"的路径，作为 `expect` 传给 Jev；
- 核验：文件存在，且行数等于页面总数。

跑出来的经验（例如"导出只导当前页"）用 `explore note` 写回手册，以后生成的计划都会带上。

## 6. 复用什么

- 网页内循环：ego-jev 的 `runJevLoop`（MIT）。它已经做了"观察 → Jev 选操作和目标 → Ego 执行 → 在登录/支付/自由文本/低置信时上交"，REPLAY 不重写，只在外面套任务链，并加上桌面和提示。
- 桌面功能：cua-driver（元素树、点击、按键、截图）；系统文件对话框交给 Peekaboo（`dialog list/click`）。
- 录制：REPLAY Recorder 扩展 + 整理（v0.1 已有）。
- 任务链的块类型：借 Skyvern 的分类思路（导航/抽取/下载/等待/人工/校验/循环），不用它的代码。

## 7. 实施顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 判断接口 | `replay look --goal`：观察（网页或桌面元素树）+ Jev 一次判断，输出约 10 行候选和状态；`replay act`：统一的点击/输入/按键入口。SKILL.md 把"指挥 → look → act"写成默认循环 | 装扩展这件事全程走 look/act，指挥只读 look 的输出；记录调用指挥的次数和总耗时（v0.1 时全慢约 9 分钟） |
| P2 内循环 | `replay do "<子目标>"`：网页交给 ego-jev，桌面用同样的规则自己实现；有把握自动执行，拿不准时上交压缩视图；录制的提示加进题目 | 表单和装扩展两个用例里，大部分步骤不需要指挥参与 |
| P3 任务链 | `plan.json`：阶段、输入、完成证据、等待/轮询、人工节点；支持断点续跑；上交时把阶段状态写进文件，指挥接手后继续 | 一条"等 N 分钟再下载"的长任务可以中断后恢复 |
| P4 无结构界面 | 截图 → 框+文字 → Jev | 不用看图就能完成选文件夹窗口的操作 |
| P5 录制 → 任务链 | 整理时直接输出阶段和提示，不再是平铺的步骤；接入桌面录制 | 人演示一次网页加桌面混合的流程，能生成可运行的 plan |

v0.1 的 `replay run`（先用录制的定位器，失效再让 Jev 补救）在 P2 里并入内循环，成为"缓存 + 状态检查"这一层。

## 8. 衡量标准

每个任务记录以下指标：调用指挥的次数、总耗时、Jev 调用次数和花费、上交次数及原因、是否有独立证据证明完成。

只有一个指标被认为是成功：**有证据证明任务完成**。页面上显示"成功"不算。

## 9. 实现记录（与上文的偏差）

- **内循环没有直接调用 `runJevLoop`。** 网页和桌面共用一个与界面无关的 `innerLoop`（`src/loop.mjs`），网页一侧沿用 ego-jev 的快照解析和 DOM 候选发现（`src/web.mjs`，MIT）。原因：桌面也要用同一套规则，录制的提示（`expect`）也要进同一个循环。
- **自动执行规则**（`src/judge.mjs`）：高风险词（付款/删除/发送/提交…）一律上交，优先于任何把握度；值匹配的填写、全是表单控件时的多数票、录制提示与 Jev 一致，可以低于通用阈值自动执行；"看起来做完了"只算声明，需要独立证据。
- **桌面功能层调研（2026-10-08）**：实测 agent-desktop（Apache-2.0）在本机列窗口时一直超时，暂不可用；Peekaboo（MIT）普通点击要求录屏权限和精确窗口快照，但读系统对话框、按对话框按钮不需要截图，正好补上 cua-driver 读不到打开窗口的缺口。所以现在是 cua-driver 负责普通窗口，Peekaboo 负责系统对话框，网页内容交给 Ego（Chromium 窗口里网页元素的坐标点击不生效，改走 AX 按下）。
- **截图隐私**：截图识字前先把目标窗口调到最前，并要求 cua-driver 确认；确认不了就不截图。系统给的窗口层级不可靠，曾因此截到别的应用。
- **装扩展用例**：v0.1 全靠指挥约 9 分钟；P1 手工 look/act 178 秒、指挥 3 次；接入 Peekaboo 后 `replay do` 14 秒、指挥 0 次（Jev 自动 2 步）。
