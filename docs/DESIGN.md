# REPLAY 设计：指挥 / 判断 / 功能

## 1. 三个角色

| 角色 | 谁 | 负责 | 不负责 |
|---|---|---|---|
| **指挥** | 慢模型（全能模型，如 Opus） | 把任务拆成一串阶段、定每段的子目标和完成证据；处理异常、等待、人工节点；从录制中学习、修补技能 | 不逐个读页面元素，不判断"这个页面加载好了没" |
| **判断** | 快模型 Jev（单次约 0.4–1 秒） | 看什么：页面上哪些东西和当前子目标有关；点哪个：下一步操作哪个元素、哪个值填进哪个框；现在怎样：加载完没有、有没有报错或弹窗、这一步成功没有、子目标完成没有、是不是卡住了 | 不能打开页面、点击、打字；不能生成文字、读长内容、看像素；不做规划，也不决定风险 |
| **功能** | 慢模型手里的工具 | 打开页面、取快照/元素树、截图和看图、点击、输入、下载、系统对话框、把截图转成"框+文字" | 不做决定 |

功能属于慢模型这一侧，Jev 本身什么动作都做不了。但"慢模型这一侧"不等于每个动作都要慢模型想一轮：功能是普通代码，可以由指挥直接调用，也可以由内循环在指挥划定的范围内，自动执行 Jev 选中的那一步。

## 2. 一个任务怎么跑

```
指挥（慢）：拆出阶段 1..N，每段写好 子目标 + 可用的值 + 完成证据
  └─ 阶段 k
       内循环（快慢交替，以代码为主）：
         功能：观察（快照 / 元素树 / 截图转文字）
         判断：Jev 一次回答——哪些相关、下一步做什么、现在什么状态
         ├─ 把握高 + 动作安全可撤回 → 功能：直接执行 → 再观察
         ├─ 子目标完成 → 功能：用独立证据核验 → 回到指挥
         └─ 拿不准 / 有风险 / 要自由文本 / 读不到文字 / 卡住
              → 把 Jev 压缩后的视图（约 10 行候选 + 状态）交给指挥
              → 指挥决定，调用功能执行 → 回到内循环
  └─ 阶段之间：指挥处理等待/轮询、人工节点（扫码、审批）、失败只修这一段
```

快在两处：

1. **Jev 有把握的步骤不需要指挥参与。**
2. **需要指挥时，它读的是 Jev 压缩后的 10 行左右，而不是几千个元素或一张截图。**

"页面好了没、出错没、做完没"这类检查都交给 Jev，指挥调用的次数因此少很多。

## 3. Jev 的题型

每次观察后最多一两次请求，题目一起发：

| 问题 | 题型 | 用途 |
|---|---|---|
| 当前子目标下一步该操作哪个元素 | choice（候选 ≤255，加 `none`） | 执行或交给指挥 |
| 每个候选和子目标的相关度 | score | 生成给指挥看的压缩视图 |
| 某个值填进哪个框 | choice（只在用户提供的值里选） | 填表；没有合适的值就交给指挥，不编造 |
| 上一步成功了吗 / 有报错吗 / 弹出窗口了吗 / 子目标完成了吗 / 卡住了吗 | noul | 状态机 |

置信度不能单独放行（参考 CUA-S1：41 个错误里有 36 个是在 0.974 置信度下跳过的）。所以放行条件是：置信度够高 + 和第二名拉开差距 + 执行后状态检查通过。三者有一项不满足就交给指挥。

以下动作一律交给指挥确认：提交、支付、删除、发送，以及需要自由文本、登录或扫码的步骤。

## 4. 感知：先给文字，最后才看图

| 界面 | 观察方式 | Jev 能否判断 |
|---|---|---|
| 网页 | Ego 快照 + DOM 中可点击的元素（ego-jev 已实现） | 能 |
| 桌面 App | cua-driver 元素树（角色、名字、值） | 能 |
| 读不到结构的界面（系统选文件窗口、画布、远程桌面） | 截图 → 识别出"框+文字" | 转成文字后能 |
| 只能看图的情况 | 截图交给指挥 | 不能，最后手段 |

## 5. 录制的作用

人做一遍之后，由指挥整理出两样东西：

- **任务链草稿**：分哪几段、每段的子目标、哪些输入会变、每段怎么证明做完了。
- **每一步的提示**："上次点的是叫'导出'的按钮，点完触发了下载"。这些提示有三个用处：
  - 喂给 Jev 出题时加权，让它扫得更准；
  - 作为执行后的预期结果，用来核验这一步；
  - 录下的定位器作为一层缓存：先用它试，试完照样让 Jev 检查状态，而不是闭眼重放。

全程不调用模型的直接重放，只用在跑过多次都没出错的固定段落上。只要出一次错就降级回内循环。

## 6. 复用什么

- 网页内循环：ego-jev 的 `runJevLoop`（MIT）。它已经做了"观察 → Jev 选操作和目标 → Ego 执行 → 在登录/支付/自由文本/低置信时上交"，REPLAY 不重写，只在外面套任务链，并加上桌面和提示。
- 桌面功能：cua-driver（元素树、点击、按键、截图）。
- 录制：REPLAY Recorder 扩展 + 整理（v0.1 已有）。
- 任务链的块类型：借 Skyvern 的分类思路（导航/抽取/下载/等待/人工/校验/循环），不用它的代码。

## 7. 实施顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 判断接口 | `replay look --goal`：观察（网页或桌面元素树）+ Jev 一次判断，输出约 10 行候选和状态；`replay act`：统一的点击/输入/按键入口。SKILL.md 把"指挥 → look → act"写成默认循环 | 装扩展这件事全程走 look/act，指挥只读 look 的输出；记录调用指挥的次数和总耗时（v0.1 时全慢约 9 分钟） |
| P2 内循环 | `replay do "<子目标>"`：网页交给 ego-jev，桌面用同样的规则自己实现；有把握自动执行，拿不准时上交压缩视图；录制的提示加进题目 | 表单和装扩展两个用例里，大部分步骤不需要指挥参与 |
| P3 任务链 | `plan.json`：阶段、输入、完成证据、等待/轮询、人工节点；支持断点续跑；上交时把阶段状态写进文件，指挥接手后继续 | 一条"等 N 分钟再下载"的长任务可以中断后恢复 |
| P4 无结构界面 | 截图 → 框+文字 → Jev | 不用看图就能完成选文件夹窗口的操作 |
| P5 录制 → 任务链 | 整理时直接输出阶段和提示，不再是平铺的步骤；接入桌面录制 | 人演示一次网页加桌面混合的流程，能生成可运行的 plan |

v0.1 的 `replay run`（先用录制的定位器，失效再让 Jev 补救）在 P2 里并入内循环，成为"缓存 + 状态检查"这一层。

## 8. 衡量标准

每个任务记录以下指标：调用指挥的次数、总耗时、Jev 调用次数和花费、上交次数及原因、是否有独立证据证明完成。

只有一个指标被认为是成功：**有证据证明任务完成**。页面上显示"成功"不算。
