# REPLAY 路线图

REPLAY 是"缝合怪"：现成的录制、感知、执行部件拿来改，自己只写把它们串起来的一小层。

## 设计主线

**感知阶梯**（从便宜到贵，能停就停）

1. 接口：录制时看到的 XHR/fetch，能直接调就不点页面
2. 结构：Ego 页面快照（网页）/ cua-driver AX 树（桌面）——默认
3. 视觉区域：截图 → 框+文字 → Jev 选
4. 慢模型看图：只在升级时

**快慢分工**

| 谁 | 做什么 |
|---|---|
| 录制的定位器（R0） | 0 次模型调用，按最稳的顺序试 |
| Jev（R1，~0.4–1 秒） | 定位器失效时在实时页面里挑同一个元素；判断「完成了吗 / 卡住了吗」 |
| 慢模型（R2，如 Opus） | 规划、读懂演示、问用户隐含规则、写技能、接手失败、扫码/支付/自由文本 |

**完成的证据走独立通道**：文件存在且非空、行数、接口返回、消息 ID——不信页面横幅。

## v0.2 长任务工作流

不是所有东西都有 CLI，而且是长任务。需要一个小 runner：

- 步骤类型（借 Skyvern 的块分类思路）：导航 / 登录 / 操作 / 抽取 / 下载 / 代码 / HTTP / 等待 / 人工 / 校验 / 条件 / 循环 / 通知 / 桌面
- 检查点、断点续跑、状态持久化
- 等待与轮询（例如「每 10 分钟看一次进度，完成后下载」），进程退出后可唤醒
- 人工节点：扫码登录、审批——`handOff` 给用户，确认后继续
- 失败只修出错的那一块，不整条重录

## v0.3 桌面
